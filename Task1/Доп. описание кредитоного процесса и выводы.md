# Описание кредитного процесса по шагам
---

## Шаг 1. Подача заявки в отделении

Клиент приходит в отделение банка. Сотрудник фронт-офиса оформляет кредитную заявку в АБС и сообщает клиенту, что заявка будет рассмотрена банком. На этом этапе клиент не получает предварительного решения — ни предодобренного предложения, ни быстрой оценки.

Ограничение: подать заявку через интернет-банк или сайт нельзя. Сайт содержит только маркетинговую информацию, интернет-банк ограничен платежами и текущими счетами.

## Шаг 2. Передача заявки в кредитный конвейер (batch, раз в сутки)
Заявка сохраняется в АБС и раз в сутки через интеграцию по базе данных передаётся в кредитный конвейер. Это первая точка задержки: между оформлением заявки и началом её рассмотрения может пройти до 24 часов.

## Шаг 3. Рассмотрение заявки в кредитном конвейере
Сотрудник кредитного бэк-офиса открывает заявку в кредитном конвейере и изучает её детали. В процессе рассмотрения конвейер через API (синхронно) вызывает систему кредитного скоринга.

## Шаг 4. Кредитный скоринг
Система скоринга формирует рейтинг клиента на основе модели машинного обучения. Источники данных:

!!! Данные из АБС и кредитного конвейера поступают в скоринг раз в сутки, то есть скоринг может работать на данных, актуальных на начало дня. Только запрос в БКИ выполняется онлайн.

## Шаг 5. Принятие решения

На основании рейтинга, возвращённого системой скоринга, и параметров кредитной заявки сотрудник кредитного бэк-офиса вручную принимает решение о выдаче кредита. Автоматического решения нет — это вторая точка задержки и ключевое ограничение для перехода к «одобрению за один день».

## Шаг 6. Передача решения в АБС (batch, раз в сутки)
При одобрении кредита заявка переходит в финальный статус. Раз в сутки эта информация через интеграцию по БД передаётся обратно в АБС. Это третья точка задержки: между решением сотрудника и фактическим зачислением средств может пройти до 24 часов.

## Шаг 7. Зачисление кредитных средств
АБС проводит платёж и зачисляет кредитные средства на счёт клиента.


# Узкие места

|№|Узкое место|Влияние на бизнес|
|---|---|---|
|1|Заявка подаётся **только в отделении**|Нет онлайн-канала привлечения молодых клиентов; зависимость от физического визита|
|2|**АБС → КК: batch раз в сутки**|Задержка до 24 часов перед началом рассмотрения|
|3|**КК → АБС: batch раз в сутки**|Задержка до 24 часов между одобрением и зачислением средств|
|4|**Ручное принятие решения** сотрудником|Не масштабируется, зависит от загрузки бэк-офиса, не позволяет мгновенных предодобренных решений|
|5|**Данные в скоринг из АБС и КК — раз в сутки**|Скоринг может работать на неактуальных данных; риск неточной оценки|
|6|**Сайт и партнёрский кол-центр без системной интеграции**|Нет возможности подать заявку с сайта; партнёрский кол-центр работает только по скриптам|
|7|**Нет предодобренных предложений**|Клиент не видит потенциального решения сразу, как у конкурентов; цикл рассмотрения — до недели вместо одного дня|
# Связь с целями бизнеса

Текущий процесс **не соответствует** финальной цели через год: клиент должен подавать заявку на кредит в интернет-банке и на сайте и получать решение **в течение одного дня**, если данных достаточно. Для этого потребуется:

- реализовать подачу заявки из интернет-банка и с сайта;
- заменить batch-интеграции АБС ↔ КК на онлайн-взаимодействие (API/события);
- автоматизировать принятие решения на основе скоринга (предодобренные предложения);
- обеспечить актуальность данных для скоринга в режиме, близком к реальному времени;
- интегрировать сайт и партнёрский кол-центр с кредитным конвейером.

Эти изменения — предмет следующих заданий спринта (целевая архитектура, план трансформации).
